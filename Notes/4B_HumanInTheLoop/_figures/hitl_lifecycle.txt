──────────────────────────────────────────────────────────────────────────
key invariants
──────────────────────────────────────────────────────────────────────────
- The tool function is called TWICE: once to request, once on resume.
  Make the pre-confirm path side-effect free.
- The pause survives a process restart IFF the session backend is durable
  (DatabaseSessionService / VertexAiSessionService / SqliteSessionService),
  not InMemorySessionService.
- Resume identity = invocation_id + function_call_id. Bind both to the
  authenticated user on resume; anyone holding the ids can fake-approve.
- The same pattern works for workflow-graph pauses — see
  RequestInput in 06_GraphWorkflows/07_HumanInTheLoop. Different event,
  same suspend/resume contract.
